## 一、已确诊的问题（带证据）

### P1 追问卡是假的，而且不是上游功能 —— 最严重

- 位置：`src/ui/web/js/app.js:1833` `buildFollowupPrompts()`。
- 行为：按「有没有 artifact / 有没有代码块」返回**三套写死文案**，与对话内容零关系。
  默认那套恒为「展开方案 / 行动清单 / 边界分析」。
- **上游不存在这个功能**：对上游 2429 个模块做三个定向探针
  （`nextSteps|suggestedFollowUp|followUpSuggestion|suggestionChips`、
  `what would you like to do next`、`try asking|you could also ask`）—— **全部 0 命中**。
- 实测危害：会话 `2026-11-08T11-44-52_9d93d2` 里，用户点了「展开说说实现方案和步骤」
  （写死那张卡），随后连续出现 3 次「[系统] 上一条回复只有思考过程、没有正文」的补救轮。
  假卡片直接制造了浪费的回合。

### P2 引擎权限模式被写死，用户选择被忽略

- `src/ui/gui-server.js:242` 把引擎调用写死 `permissionMode: "acceptEdits"` ——
  用户在界面上选「接受编辑 / 自动 / 全部放行」**完全不影响引擎**。
- `src/engines/claude-code.js` `buildEngineArgs()` 只认 4 个值
  （`default|acceptEdits|plan|bypassPermissions`），**其它值静默降级成 acceptEdits** ——
  MyClaude 自己的 `ask / auto / dontAsk` 全部落进这个静默降级。

### P3 引擎拿不到额外工作目录

- MyClaude 有 `config.additionalDirectories`（`/add-dir` 维护，自研 agent 会用），
  但 `buildEngineArgs()` **从不把它传给引擎** —— 引擎只能碰项目目录。
- 实测表现（会话原文）：「用户级技能目录 `C:\Users\Admin\.claude\skills` 被本会话沙箱挡了
  （只允许访问项目目录），我没能直接列它」。

### P4 `.claude/skills` 是上游硬保护目录，失败信息把用户晾住

- 上游 `chunk-zvergrz0.js` 的 `Ef()`：路径落在 `.claude/commands|agents|skills` 下即返回 true；
  调用方 `PG()` 对这类路径**一律要求显式授权**（`haven't granted it yet`）。
- `--print` 模式下没有人能应答授权提示 → 必然被拒。
- 结果：用户说「做成技能」，模型写 `.claude/skills/beef/SKILL.md` 永远失败，
  而 MyClaude 没有把「为什么失败、怎么办」讲清楚。

### P5 「只有思考过程、没有正文」反复触发

- 机制在 `src/agent/agent.js:745`（`ensureFinalAnswer`）。
- 实测：同一会话内连续触发 3 次，说明补救策略没收敛。
- 待审计：该机制是否也作用于 upstream 引擎回合（会话标记 `engine: upstream` 却出现该消息）。
